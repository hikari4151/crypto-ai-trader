# 性能优化项目清单（2026-09-22）

来源：会话中实测数据 + 代码扫描。目标：识别可落地的性能优化机会，按收益/风险/工作量排优先级。

## 1. 性能现状基准（实测）

| 项 | 数据 |
|---|---|
| 训练一轮（5000 根 5m，8ep×8n×8p） | **9.5 秒**（每 episode ~1.2s）——训练侧快，无需优化 |
| 长窗观测（30+90 天回放） | 每轮 **+数分钟**（撮合逐根 Python）——已用 `every_n=5` 降频缓解 |
| 部署长窗门（30d 回放） | 冠军/晋升轮 +1~2 分钟（可配加 90d 档 +2~4 分钟） |
| 信号门数学分析 | 每个 buy 信号触发一次 `compute_latest`+`math_analysis`（O(150根) 毫秒级，但可缓存） |

## 2. 热点识别（代码级）

1. **回测撮合循环 `backtest/engine.py::run_matching_loop`**——逐根 K 线 Python 循环，是 30/90 天长窗回放慢的根本原因（rl_adaptive 不支持 fast_engine 向量化路径）；
2. **`indicators/technical.py::compute_latest`**——每次 O(最近N根) 全量重算；AI 数学期望信号门每个 buy 信号都调一次（毫秒级，但高频）；
3. **长窗回放数据拉取**——`load_klines_cached` 每次拉 8640/25920 根（有缓存，但每冠军轮仍重复拉取）；
4. **大模块维护性**——`drl/evolve_engine.py` 240KB / 3977 行（功能完整但导入与协作成本高，非运行性能）。

## 3. 优化候选项目（按优先级）

### P1-① 信号门数学分析缓存（✅已落地 2026-09-22）
- 现状：每个 buy 信号调 `compute_latest` + `math_analysis`（O(150) 重算）；
- 优化：按 (symbol, timeframe, 最新K线时间戳) 缓存最近一次分析结果，同一根 K 线内的多个信号复用；K 线更新后失效；
- 落地：`ai/math_gate.py::math_ev_cached`（key=最新K线时间戳，缓存超限清空，无 candles 不缓存）+ `engine._math_ev_cache`；信号门块改为缓存路径；TDD 3 用例（同 K 线复用/新 K 线失效/无 candles 不缓存）→ `tests/test_math_ev_gate.py` **10/10**，关键子集 38+ passed；
- 收益：信号门路径从毫秒级进一步下降（高频信号场景明显）；风险：低；工作量：小（已完成）。

### P1-② 回测撮合加速——✅特征侧已落地（2026-09-23），因子侧待专项
- **实测基线**：500 根回放 4.5s（每根 ~9ms）；30d≈80s、90d≈4min；
- **热点量化**：特征 `_precompute_features` 2.06s + 因子 `CompositeFactorEvaluator.eval` 2.22s ≈ **97%**（每根全窗口 400 根重算只用末行；截断不可行——ewm/expanding 全历史）；
- **✅特征侧落地（2026-09-23）**：新模块 **`drl/streaming_features.py::StreamingFeatureEngine`**——13 特征**增量**计算（rolling/EWM 状态每根 O(1~w)），对照测试 `tests/test_streaming_features.py` **5/5**（3 seed × 1000 根）证明与 `_precompute_features` **逐位一致（13 列 diff=0）**；接入 `rl_adaptive.on_candle`（update 从第 1 根起累积，保证状态堆叠口径）；
  - **回放对照**：2000 根 ret 改前 +0.024332 / 改后 +0.024007（差 3.3e-5，浮点级 <0.01%），**trades 61=61 完全一致**；**提速 2.03x**（19.9s→9.8s）；关键子集 39+ passed；
- **✳️因子侧：不可安全流式化（2026-09-23 实证结论，已关闭）**：`eval` 每根对"最近 400 根窗口"**重算**（EWM/expanding 从**窗口起点**重新开始）；流式持续累积跨窗口——**>400 根后窗口起点滑动，两者语义冲突**（实测：adx 窗口首值 pandas=0 vs 流式=13.38，合成 diff≈0.08）；强行流式会改变部署因子口径（需重训模型，不可行）。
- **✅因子侧小型优化（2026-09-23 追加）**：`CompositeFactorEvaluator.eval` 的 expanding z 改为 **numpy 快速路径**（跳过 NaN、ddof=1，与 pandas expanding **逐位一致，对照 max diff≈4e-15**——compute_factor_matrix 3.9ms/根仍占 78%，保持"窗口重算"语义不可动）；`rl_adaptive._factor_value` **缓存 evaluator 实例**（reset 重建）；实测 500 根 on_candle 完整路径 **2.44s→1.92s（~21%）**、2000 根回放 **9.8s→8.53s**（相对原始 19.9s 共 **2.33x**）；注：后续计时对照中 flat 已被 v55 替换（best 轮换），指标差异属模型更新非优化引入（numpy 路径逐位等价已单独验证）。

### P2-③ 长窗回放并行与数据复用（✅已落地 2026-09-22）
- 30d 与 90d 窗口共用同一数据源（90d 数据可切出 30d 段），避免重复拉取/预处理（原有）；
- 两档回放改为**并行**（`asyncio.gather` + `to_thread`）：`_observe_strategy_drl_longwindow` 与 `_candidate_longwindow_gate` 均并行多窗口；
- 收益：部署门（开 90d 档时）耗时从串行 3~6 分钟降到 ~3 分钟；TDD 保障（90d_fail 测试改为按数据长度判档，并行时序无关）→ `tests/test_evolve_longwindow.py` 13/13；关键子集 38+ passed。

### P2-④ evolve_engine.py 模块拆分（维护性）——✅两阶段全部落地（2026-09-22）
- 240KB 单文件 → 按训练/观测/部署/族群拆分；
- **第一阶段（已完成）**：4 个纯判定函数（`_should_rollback`/`_should_from_scratch_reset`/`_oos_gate_passed`/`_longwindow_verdict`）抽到新模块 **`drl/evolve_rules.py`**（77 行），evolve_engine.py 模块级 import 保留导出名——文件 3991→3930 行；
- **第二阶段（已完成）**：4 个观测方法（`_observe_strategy_drl_walkforward`/`_observe_gap01`/`_observe_strategy_drl_longwindow`/`_candidate_longwindow_gate`，405 行）抽到新模块 **`drl/evolve_observations.py` 的 `EvolveObservationsMixin`**，`class EvolveEngine(EvolveObservationsMixin)` 继承（self 仍为引擎实例，依赖不变）——evolve_engine 3930→**3526 行**；
- 验证：观测相关测试（longwindow/gap01/walkforward_obs/refetch/math_ev_gate/train_cfg）**46+ passed** + imports OK；
- 收益：evolve_engine.py 240KB→约 200KB（减 405 行），模块职责清晰（rules=纯规则、observations=观测、engine=训练/部署/族群）。

### P3-⑤ K线拉取本地持久化缓存——✅已内置并验证（2026-09-22）
- **项目已实现**：`backtest/kline_store.py` + `load_klines_cached`——本地优先 + 增量补尾 + 历史回填（binance endTime 向前翻页）；
- **验证**：ETH/USDT 5m 本地覆盖 **26210 根**（约 90 天）；运行日志"拉取 ETH/USDT 5m 共 2 根"即增量命中（本地已有旧数据只拉新 K 线）；
- 结论：无需新实现（避免重复造轮子），本项关闭。

## 4. 本会话已落地的性能相关优化
- **训练速度实测**：训练 9.5s/轮（确认非瓶颈）；
- **长窗观测降频**：`evolve_strategy_drl_longwindow_every_n=5`（每轮耗时从数分钟回到 ~10s）；
- **部署门窗口可配**：30d 门槛 + 可选 90d 档（控制冠军轮成本）。

## 5. 建议
先做 **P1-①（信号门分析缓存）**——低风险、立即见效、TDD 可控；P1-②（撮合加速）收益最大但需独立专项（建议单独排期，配回归对照测试）。
