# 持续进化引擎：指定品种/指定时间周期训练 专案论证

> 结论先行：**「固定品种 + 固定周期」不会凭空比「轮换 + 跟随默认周期」更好，也不能一概而论——两者是不同目标下的正确解。** 本项目不选边，而是把两者都做成可配置能力（后端 `evolve_symbols` / `evolve_timeframe` + 前端「训练配置」面板热更新），由用户按当前目标选择，并给出切换方法与预期差异。

---

## 一、现状与本次落地的能力

### 现状（本次改动前）
- 训练标的池：`evolve_symbols = ["BTC/USDT", "ETH/USDT", "SOL/USDT"]`，因子挖掘/策略 DRL/元控制器三条管线每轮 `_next_symbol()` 轮换取一个标的训练；
- 训练时间周期：三条管线一律使用全局 `settings.default_timeframe`（默认 1h），与**实盘交易周期绑定**。

### 本次落地的能力
| 能力 | 实现 |
|---|---|
| 固定品种训练 | `evolve_symbols` 允许单元素（如 `["BTC/USDT"]`），轮换自然变成固定品种；前端「训练配置」面板可编辑保存，热更新 + 写回 config.yaml |
| 独立训练周期 | 新增 `evolve_timeframe`（留空=跟随 default_timeframe），三条训练管线统一走 `_effective_timeframe()`：拉数、demo 兜底、落库、flat 元数据、注册 base_timeframe 全部用实际训练标的与周期 |
| 前端入口 | 持续进化面板「训练配置」卡：训练标的池（逗号分隔）、训练时间周期下拉、间隔/窗口/回退阈值/vol_penalty/OOS 门槛/增量门槛/跨标门，一键保存热更新 |

## 二、逐点对比：固定品种+固定周期 vs 轮换+跟随周期

### 1. 数据多样性与过拟合

| 维度 | 轮换（现状默认） | 固定品种 |
|---|---|---|
| 样本多样性 | 3 个标的不同波动率/趋势形态 → 策略泛化面广 | 单一标的分布更纯 |
| 过拟合风险 | 低（对立面数据稀释单标特征） | 高（容易拟合该标的噪声） |
| 结果可解释性 | 差（fitness 是混合标的的平均） | 好（每轮都对应同标的同周期） |

**判断**：如果目标产出「用于实盘的通用交易策略」，轮换更好；如果目标是「针对某标的做专业策略」（例如只交易 BTC），固定品种更合理——前提是 OOS/跨标门继续开着防过拟合。

### 2. 收敛速度与信噪比

- **固定品种**：同一分布上反复迭代，PPO 策略梯度收敛快、一轮一个准；但可能收敛到该标的局部最优。
- **轮换**：每轮分布切换（BTC 高波动 ↔ SOL 高波动/低流动），状态/收益分布漂移，收敛更慢，信噪比更低；好处是策略被迫学「不变要素」。

**判断**：短周期（如 5m/1h 快速上线验证）选固定品种测得更快；长期打磨选轮换更稳健。

### 3. 与实盘交易周期的匹配

现状的隐患：**训练周期 = 实盘周期**。若实盘 default_timeframe=1h，训练也 1h——这是「自洽」，但也是「没得选」：
- 想要更高频交易（如 5m）但实盘还是 1h？现在 5m 策略没地方训。
- 想要用 4h 过滤噪声只做趋势？也训不了。

`evolve_timeframe` 落地后，训练与实盘解耦：
- **一致**（推荐常规）：`evolve_timeframe` 留空跟随 default_timeframe → 信号与回测同口径；
- **隔级**：训练 1h、交易 15m/30m（策略在更细周期上外推）——适合「低周期执行、中周期决策」的玩法，但需接受外周差异；
- **主次**：训练 15m、交易 1h 聚合——细周期特征找信号，粗周期持仓降成本。

### 4. 跨标 OOS（P1-8）与固定品种的兼容

本次改动的关键约束：跨标 OOS 只有在**未注入级联因子**时可行（factor_values 增列会破坏跨标状态维对齐）。固定品种模式下该机制不受影响，但注意：
- 固定品种时 `_cross_symbol_oos` 会取 `_symbols` 里另一个标的评估——单元素池没有「另一个标的」，评估自动退回同标 OOS。这是**可接受的降级**：固定品种追求的可解释性换了统一性。
- 若仍需跨标传导评估，建议在固定品种时保持 2-3 个标的池、只把「训练聚焦」标的第一位，配合 `current_symbol` 展示。

### 5. 数据量与增量门（P2-11）

- 固定品种（如 BTC 1h）：单标数据量小，增量训练触发频率低（默认 2 根新 K 线 ≈ 2 小时），适合长线低频策略；
- 轮换 3 标的 5m：数据量大，训练频率高，适合高频打磨。
- 固定品种 + 极短周期（如 1m）反而数据充足，收敛也快——这是「固定」比「轮换」在高频场景的隐藏优势：**同一根轴上不停积累样本**。

## 三、推荐的组合用法

| 目标 | 配置建议 |
|---|---|
| 通用跨品种策略（默认） | `evolve_symbols` 留 3 标的，`evolve_timeframe` 留空跟随 default |
| 专注 BTC 的日线/4h 趋势策略 | `evolve_symbols: ["BTC/USDT"]`，`evolve_timeframe: "4h"`，OOS 门槛保持 250，跨标门开 |
| 快速验证某周期信号 | `evolve_symbols: ["ETH/USDT"]`，`evolve_timeframe: "15m"`，增量门槛调低（1）加速迭代 |
| 高低周期配合 | `evolve_timeframe: "1h"`，实盘 default_timeframe 保持 15m/5m，关注外周差异 |

> 落地入口：Web「持续进化引擎」页 → 训练配置卡 → 修改后「保存配置」。保存即热更新并写回 `config/config.yaml`，重启不丢。

## 四、结论

1. **固定品种+固定周期「会不会更好」取决于目标**：追求单标专业化、快速收敛、信号与训练标的一致 → 固定更好；追求通用性、抗单标过拟合、样本多样性 → 轮换更好。当前默认（轮换+跟随）是「通用策略」路线的合理默认，也是多数用户的第一需求。
2. **原来最大的问题是「没得选」**：周期与实盘绑定、品种只支持固定 3 标的。本次已把两者都参数化并热更新上线，用户不再被迫选边。
3. **启用固定品种时的注意点**：过拟合风险上升（建议保留 OOS 门与回退保护，本次 P0-3/P0-4/P1-5/P1-6 已加固）；单元素池时跨标 OOS 自动降级为同标评估，属预期行为。
