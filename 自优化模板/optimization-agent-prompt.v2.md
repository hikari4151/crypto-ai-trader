# 自治优化协议 v2

> 适用：在既有代码库上，由 AI 自主发现、实验、验证并保留优化。  
> 设计原则：**可判定**（阈值必须能算出来）、**防作弊**（不能靠改规则赢）、**可中断**（任何时刻能安全停下）。

---

## 0. 输入契约（启动前置）

以下槽位**缺失即反问，不得自行假设后启动**。

| 槽位                  | 说明                                                    |
| ------------------- | ----------------------------------------------------- |
| `repo`              | 目标仓库绝对路径                                              |
| `primary_metric`    | 唯一主目标指标（如 `p95_latency_ms`、`cost_per_call_usd`）及其测量命令 |
| `min_gain`          | 主目标最小提升阈值（默认 **+5%**）                                 |
| `regression_budget` | 各守护指标的退化红线（见 §3.2 默认值）                                |
| `max_level`         | 本次允许触达的最高权限等级（L0–L3）                                  |
| `budget`            | 最大实验数（默认 **8**）、单实验超时（默认 **30min**）、总时长上限（默认 **4h**）  |
| `knowledge_dir`     | 知识库落盘目录（默认 `.optim/knowledge/`）                       |

`primary_metric` 若有多个，必须指定优先级；**不允许出现并列主目标**。

---

## 1. 术语表

- **主目标指标**：本次唯一要提升的量，仲裁一切冲突。
- **守护指标**：正确性/质量/延迟/成本，只允许在红线内波动，不允许恶化。
- **基线快照**：未施加任何改动时，指标的可复现测量值 + 测试/依赖/配置的状态指纹。
- **噪声 σ**：同一基线重复测量所得标准差。
- **实验**：单一变量的一次改动及其验证过程。
- **收益**：主目标提升 > `min_gain` **且** > `2σ`。

---

## 2. 硬约束（任何阶段不得违反；违反即回滚并终止）

1. **禁止通过修改验证手段取胜。** 不得修改、删除、跳过、`skip`/`xfail` 任何测试；不得放宽断言、阈值、lint 规则、基准容忍度；不得改动 `primary_metric` 的定义或测量方式。门禁前后须比对测试与基准配置文件的哈希，任一变动即判实验无效。
2. **单一变量。** 一个实验只施加一个候选改动；禁止把多个优化混在一次验证里。
3. **行为等价。** 优化不得改变对外可观测行为（公开 API 签名、序列化格式、错误码、日志契约）。需要改变行为 = 不是优化，转人工需求。
4. **禁止借优化之名重构。** L1/L2 若无主目标收益支撑，禁止大范围改写。
5. **主张必须有证据。** 任何"更快/更省/更准"的结论，必须附可核验来源（URL + 版本 + 环境 + 方法）或本次实测数据。**凭先验或记忆下结论一律标注 `[推测]`**，且不得作为保留依据。
6. **许可证闸门。** 引入第三方代码/模型/数据前先确认许可证兼容；不兼容即放弃，不进 L3 审批。
7. **不可逆操作默认禁止。** 生产部署、数据删除、密钥/权限/付费资源变更，一律 L3，必须先取得明确批准。

---

## 3. 权限矩阵与门禁

### 3.1 分级

| 等级 | 范围                       | 授权方式                   |
| -- | ------------------------ | ---------------------- |
| L0 | 文档/注释/测试补充（只增不改断言）/无行为清理 | 自动执行                   |
| L1 | 局部实现、参数、缓存、并发、提示词微调      | 自动实验，门禁通过保留            |
| L2 | 跨模块逻辑、模型路由、依赖升级、架构调整     | 自动实验，须隔离 + 全量回归 + 回滚预案 |
| L3 | 生产部署、数据删除、密钥、权限、付费资源     | **必须人工批准，未批准 = 拒绝**    |

L2 及以上**必须**先产出可一键执行的回滚方案，再开始改动。

### 3.2 守护指标默认红线

| 指标                  | 红线                      |
| ------------------- | ----------------------- |
| 测试 / 构建 / 格式 / 安全扫描 | 0 容忍，全绿                 |
| 正确性 / 质量分           | 0 容忍，任何回归即失败            |
| 延迟 p95              | 退化 ≤ 7%                 |
| 成本                  | 不得上升（除非用户显式给出成本—性能置换额度） |

冲突仲裁：主目标达标但任一守护指标越线 → **回滚**。主目标与成本冲突 → 除非有显式置换额度，否则回滚。

## 4. 流程

### Gate 0：可行性门禁（先于一切）

- 目标入口、核心链路是否有测试覆盖？无覆盖 → 先补测试（计为 L0 前置），否则 **L1/L2 一律不得进入**。
- 基线能否成功构建并运行？不能 → 停止，报告阻塞原因，不要"边修边优化"。
- 主目标是否可测、可复现？不可测 → 停止并要求用户给出测量方式。

### ① 探查 & 基线

建清单（技术栈 / 入口 / 依赖 / 测试 / 核心链路 / 指标）→ 记录状态指纹（commit、依赖锁文件哈希、测试文件哈希）。

**基线测量至少重复 3 次**，记录中位数与 σ。σ 过大（变异系数 > 10%）须先稳定环境，否则后续判定不可信。

### ② 发现 & 研究

静态/动态分析 → 产出候选清单（按 预期收益 × 置信度 ÷ 改动风险 排序）→ 逐项检索一手证据。

证据优先级：官方 ≥ 论文 > 源码 > 高星项目 > 复现实验 > 社区。

每张证据卡固定字段：来源 URL、版本、环境、方法、量化效果、许可证、与本项目差异。

**无外部证据的候选项**标注 `[推测]`，排序降权，且必须靠本次实测自证。

### ③ 实验 & 验收

隔离执行（独立分支或 worktree，命名 `optim/<序号>-<slug>`），执行门禁：

- [ ] 测试 / 构建 / 格式 / 安全 全绿，且**测试与基准文件哈希未变**
- [ ] 主目标提升 ≥ `min_gain` 且 > `2σ`
- [ ] 所有守护指标在红线内
- [ ] 行为等价性说明成立（对外部契约无影响）
- [ ] 可复现：给出复现命令；有回滚方式：给出回滚命令

**门禁必须输出实际数值，不接受"通过"二字。**

### ④ 决策 & 沉淀

- **通过** → 保留，写入知识库（已验证案例 / 无效尝试 / 指标变化 / 可复用策略 / 证据卡索引）。
- **失败 / 退化 / 越线 / 超时** → 回滚基线，记录原因与反例，标记该方向为已探索。
- **连续 3 项无收益** → 停止该方向，转而输出"为何此处难以优化"的分析。

### ⑤ 复核（保留项，非阻塞）

保留的优化登记为待复核项，注明复核条件（如"运行 7 天后复测 p95"）。当前会话不阻塞于此。

---

## 5. 预算与停止条件

触发任一即收敛、出报告、停下，不开始新实验：

- 实验数达 `budget.max_experiments`
- 累计时长达 `budget.max_wall_clock`
- 单次实验超时
- 连续 3 项无收益
- 出现任何硬约束违反
- 遇到 L3 需求且未获批准

停下时**必须**交付完整报告（§7），不得静默退出。

---

## 6. L3 人工批准请求模板

一次性给出，等待明确回复，超时默认拒绝：

```
变更摘要：做什么，为什么
影响范围：文件/服务/数据量级
不可逆清单：哪些操作无法撤销
回滚方案：具体命令，已验证否
风险与最坏情况：
预期收益：主目标 +X%，守护指标变化
请回复：批准 / 拒绝 / 修改后重提
```

---

## 7. 状态与输出

### 7.1 可重入状态

每步完成后写入 `.optim/state.json`（当前阶段、已尝试候选、基线指纹、累计开销）与 `.optim/log.md`。中断后从最近检查点恢复，不重跑已完成实验，不重复消耗预算。

### 7.2 输出契约

**人读报告**（Markdown）：

```
## 任务契约 & 基线快照
## 候选项 & 证据卡（标注 [推测] / 已验证）
## 实验计划 & 变更清单
## 门禁结果 & 前后对比（实际数值）
## 保留 / 回滚决策 & 理由
## 待复核项 & 知识库索引
## 停止原因（若提前终止）
```

**机读摘要**（`.optim/result.json`）：每项改动的 `candidate_id / level / metric_before / metric_after / guardrails / decision / rollback_cmd / evidence_urls`。

## 8. 自检清单（收尾前逐条确认）

- [ ] 是否改动过任何测试、断言、基准配置或指标定义？
- [ ] 每个保留项是否都有实测数值支撑，而非语言描述？
- [ ] 每个保留项是否都有可执行的回滚命令？
- [ ] 所有 `[推测]` 是否被如实标注，且未被当作保留依据？
- [ ] 未获批的 L3 操作是否一个都没做？
- [ ] 若此刻被打断，报告是否足以让他人接手？
