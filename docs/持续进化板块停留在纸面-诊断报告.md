## 0. 结论速览（TL;DR）

**持续进化板块不是"没实现"，也不是"没在跑"——三条训练循环现在全部活着、每 5 分钟都在真实验证；但它恰好卡在了自己设定的"上线门禁"上：**

| 管线 | 实时状态（2026-09-19 14:49 抓取） | 卡点 |
|---|---|---|
| factor_miner（因子挖掘） | running ✅ / `stalled=true`，连续 28 轮未接受 | 锚点 fitness=0.2373（v307，09-18 21:26 接受）太高，新模型 0.09~0.21 全部 `new < 0.2373×0.95` → **每轮回退** |
| strategy_drl（策略 DRL） | running ✅ / `stalled=true`，连续 32 轮未接受 | **级联因子注入断裂**（21 次"窗口尾时间戳不一致，拒绝注入"、0 次注入成功）→ 模型无因子特征 → OOS 段 `position_ratio=0.000` 不交易 → 全部被"OOS 硬门 / 回退"拦下；最后接受 v21（09-18 20:36，oos_ret=0.006014） |
| meta_controller（元策略） | running ✅ / `stalled=true`，连续 16 轮未接受 | 501 轮里 **489 轮被拒（97.6%）**，OOS 收益稳定在 **-0.20 ~ -0.22**（样本外不交易/亏钱）；锚点因缺 `model` 身份字段被判定不可比；最后接受 v286（08-31，oos_ret=0.01752） |

**三个叠加的"纸面"机制：**

1. **引擎在跑、验收不过**：OOS 硬门 + 回退保护把"接受/部署"的门槛订得和实盘一样高，真实 5m 行情很难稳定给出正 OOS → 版本不涨、轮次全红是常态。
2. **产物即使被接受也不会接管实盘**：当前策略是 `dual_ma`，`deploy_model` 的运行时热加载一律 `skipped`（今日日志 32 次"部署失败…当前策略 dual_ma 非部署目标"）——进化产出只注册进策略库，不作用于正在运行的引擎。
3. **整个程序按自己的定义就还在纸面**：`docs/LIVE_READINESS.md` 的实盘门 E1/GAP-01 要求"真实数据 OOS 正期望 + 跨品种 + 成本鲁棒"，2026-09-18 P0 实测没有任何内置/候选策略通过（进化产物也在其中）。

## 1. 本仓库里「纸面」指什么

`docs/LIVE_READINESS.md` 开头定义：本文档回答「**脱离纸面（paper/simulated）之前，还缺什么**」；§1「脱离纸面」= 用真实资金在真实交易所 live 无人值守运行，前置 E1 = **真实历史数据、扣除成本后的 OOS 正期望**。

所以"持续进化板块停留在纸面上"在本仓库语境下是双重含义，且指向同一件事：
- 进化产出的策略从未证明真实数据 OOS 正期望（GAP-01，最致命）；
- 引擎内部也极少有模型能通过部署门禁，导致"训练成功"和"可用成果"之间长期断层。

## 3. 三管线当前卡点明细（含代码位置）

### 3.1 factor_miner：被自己的锚点压住（今天才开始，不是历史遗留）

- 锚点：`data/models/factor_miner/meta.json` → `best_v=307, best_f=0.2373`（09-18 21:26 接受，与 `_cascade_report_ETH_USDT.json` round800 同一轮）。
- 今日日志连续出现：
  > `因子挖掘新模型退化 (new=0.0950 < old=0.2373*0.95)，回退到最佳版本`（new 在 0.09~0.21 之间波动）
- 回退判据：`drl/evolve_engine.py` `_should_rollback()`（L106）——旧 fitness 为正时 `new < old × 0.95` 即回退。0.2373 的锚点意味着每轮至少要 0.2254 才能不被回退，当前窗口供不出。
- 实时 `reject_streak=28` → 已触发自动降频（60s→300s），但不会因此重置锚点。
- **注意**：这 28 轮是 09-18 21:26 之后才开始的，不是长期冻结；说明因子挖掘"时好时坏"。

### 3.2 strategy_drl：级联因子注入断裂 → 模型样本外不交易（当前主卡点）

- 级联链路：factor_miner 每轮把组合因子值写成 `_cascade_factor_values_ETH_USDT.npy` + 尾时间戳 companion JSON；strategy_drl 训练前用 `_load_cascade_factor_values()`（L3033）加载并校验窗口尾时间戳。
- 今日日志 21 次、0 次成功：
  > `级联因子窗口尾时间戳 1789737900 与当前数据 1789788300 不一致（窗口已右移？），拒绝注入`
- 后果：策略 DRL 拿不到因子特征 → 训练出的模型在 OOS 段不交易：
  > `OOS 段几乎无信号(position_ratio=0.000)，样本外未交易，暂不部署`
  > `策略DRL新模型退化 (OOS 0.0000 < 0.0060×0.95)，回退到最佳版本`
- 实时 `reject_streak=32`（7→32 一路上升），已降频到 300s。
- 版本档案（完整读取，修正初稿）：`strategy_drl` 最后接受 **v21（09-18 20:36，oos_ret=0.006014）**；v19（09-16）、v20（09-18 20:26）也接受过。**不是 13 天冻结，是 v21 之后 ~17 小时连续 32 轮被拒/回退。**
- 额外发现（`server.err.log`，09-05 已在发生）：即使级联注入成功，模型也会因依赖"预计算因子列"而**导不出 Pine**：
  > `rl_evolve 无法导出 Pine：…第 55 维为预计算值…Pine 端无法逐根K线重建`
  于是形成死锁：**注入因子 → 策略有信号但无 Pine 代码；不注入 → 有 Pine 代码但模型不交易。**

### 3.3 meta_controller：489/501 轮被拒，OOS 稳定为负

- `data/trader.db` → `evolve_rounds`：
  - `oos_rejected=489`、`rollback=12`、`ok=0`（501 条保留行中无 ok；v286 是旧代码时代的接受）。
  - 最近 10 轮全部 `oos_rejected`，`fitness≈-0.22`、`oos_ret≈-0.21`、`position_ratio=0.0`（OOS 段基本不交易或亏钱）。

## 4. 部署热加载被跳过：产物不会接管运行实例（32 次）

即使某轮模型通过全部安检，`deploy_model` 的运行时热加载也会被跳过：

> `部署失败(factor_miner v307): reload 未成功 {'status':'skipped', … 'reason':'当前策略 dual_ma 非部署目标'}`
> `部署失败(strategy_drl v21): … 'reason':'当前策略 dual_ma 非部署目标'`

今日 `server.log` 中该模式出现 **32 次**。原因：当前运行策略是默认 `dual_ma`，而 reload 回调只热加载与当前策略同名的模型（`engine/trading_engine.py` 的部署回调逻辑）。进化模型只是注册进策略库（`rl_evolve` 今日注册 11 次、pine 43285B），**从不改变正在跑的引擎**。

## 6. 为什么"始终只能停留在纸面"：机制汇总

1. **实盘门 = 真实数据 OOS 正期望（GAP-01）本身没过**：`docs/LIVE_READINESS.md` §3 P0 实测（2026-09-18）没有任何内置/候选策略通过；进化模型最好也只是 oos_ret≈+0.006（strategy_drl v21）这种量级，离"跨品种 + 成本翻倍仍正 + 交易样本充足"差得远。
2. **进化引擎把"接受"设成同一道 OOS 门 + 回退保护** → 训练每 5 分钟发生、验收几乎每轮失败；`reject_streak` 16~32 证明是"常态不是事故"。
3. **级联注入窗口失配**把"因子→策略"这条唯一能让 strategy_drl 产生信号的链路切断（21 次拒绝注入/0 次成功），策略 DRL 退化到"训练了但不会交易"。
4. **部署热加载对 dual_ma 跳过** → 即便接受，也不上实盘/不回测默认策略，产物只停留在"注册表里的策略卡片"这一层。
5. **Pine 与级联互斥** → 要么"能上图但不交易"，要么"会交易但上不了图"，产品化闭环缺一角。
6. **前端把"训练活动"展示得很充分，把"是否被接受"放得很弱**：主状态条只有 running/enabled/训练中；`stalled/reject_streak` 是边栏小字，用户观感=一直在进化。

## 7. 建议（仅诊断，未改代码）

按投入产出排序：

1. **修级联因子窗口同步（最快见效）**：`_load_cascade_factor_values` 的 tail_ts 校验对"滚动窗口右移"过于严格——保存端与加载端都用同一滚动窗口时，尾戳每根新 K 线都会前进，导致注入永远失效。应改为按"窗口身份（起点或长度+起点）"校验，或训练时同轮直接把因子值传给 strategy_drl（同轮共享 df），而不是落盘后再匹配。
2. **给 meta_controller 和 strategy_drl 增加与 factor_miner 同款的"连续拒绝 from-scratch 重置"**（`evolve_factor_miner_reset_after_rejects` 已有先例），打破"永久连拒/空仓懒解"。
3. **把部署热加载从"只加载同名策略"改为"接受/回退后至少把 flat 模型文件与注册表更新到位，并明确提示当前运行策略未使用该模型"**，避免"部署失败…非部署目标"被当成异常而实际是预期跳过。
4. **面板主视图增加"接受率 / reject_streak / 与锚点差距"**：把 `accepted/total`（factor_miner 251/501、strategy_drl 5/501、meta_controller 0/501）放上主卡，替代"一直在训练"的误导。
5. **解 Pine/级联互斥**：要么支持表达式因子导出（文档已提示"请改用表达式因子训练"），要么明确在 UI 标注"该进化策略仅在软件内运行、无 Pine 版本"。
6. **实盘落地优先级**：先让任一简单策略（grid 最接近）过 GAP-01 的 walk-forward/CSCV-PBO + 成本扫描，再让进化引擎以同一验收口径竞争（`docs/LIVE_READINESS.md` §3）。
