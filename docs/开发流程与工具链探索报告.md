# 开发流程与工具链探索报告（2026-09-24）

> **范围**：本仓库的开发流程与工具链（依赖管理、CI、代码质量门禁、测试、运维脚本、仓库治理）。
> **产出**：结构化建设项清单，不改代码。
> **依据**：`.github/workflows/ci.yml`、`requirements.txt`、`requirements-lock.txt`、`pytest.ini`、`ruff.toml`、`.coveragerc`、`scripts/*`、`docs/REDEV_GUIDE.md`、`README.md`、`.optim/log.md` 等。

## 0. 结论速览

当前项目**功能侧工程纪律很强**（红线清单、双引擎一致性、AI 参数门、任务并发上限、Windows 专项适配、自治优化协议），但**工具链侧存在三处系统性缺口**：

1. **CI 不可复现**：`requirements-lock.txt` 缺 `ruff` / `esprima` / `pytest-asyncio`，却包含 `winloop`、CUDA 系等 Windows/CUDA 专用包；而 CI 跑在 `ubuntu-latest` 上并安装完整 lock。
2. **门禁覆盖面不一致**：CI 的 `compileall` / `ruff` 与 `.coveragerc` 都**漏掉 `exchange/`、`factors/`**（本地验证链却包含），且 ruff 有 6 个核心文件的整文件豁免。
3. **无 Windows 平台 CI、无本地 pre-commit、无统一验证命令**：Windows 专项风险（GBK/start.bat/winloop）无法被 CI 捕获，回归全靠人肉按 REDEV_GUIDE §4 跑。

优先建议按 **P0（修 CI 依赖与覆盖面）→ P1（统一验证命令 + pre-commit + CI 增强）→ P2（类型检查/覆盖率/仓库治理渐进）** 推进。

## 2. 发现的问题（按影响排序）

### 2.1 【高】CI 依赖清单不可复现，全新 runner 上大概率跑不绿

- `requirements-lock.txt` 与 `requirements.txt` **都没有** `ruff`、`esprima`、`pytest-asyncio`：
  - `ci.yml` 第 36-37 行执行 `python -m ruff check ...`，但 lock 中无 ruff；
  - `scripts/check_js.py` 第 24 行 **顶层无条件 `import esprima`**，即使有 node 也会先因缺包 ImportError；
  - `pytest.ini` 设置 `asyncio_mode = auto`，缺 `pytest-asyncio` 时全量 pytest 无法按预期运行（REDEV_GUIDE §F8 明确记载"缺了 C/D 类异步测试全挂"）。
- 反方向：lock 第 27-46、73 行包含 `cupy-cuda12x`、`nvidia-*`、`winloop` 等 **Windows/CUDA 专用包**；`README.md` 第 52-56 行自己注明"含 CUDA/Windows 专用包，跨平台请按需裁剪"，但 `ci.yml` 在 `ubuntu-latest` 上安装**完整 lock**。
- 影响：CI 要么直接失败，要么依赖 runner 镜像里"恰好预装"的工具侥幸通过——无论哪种，都不满足"全新环境可复现"的门禁前提。

### 2.2 【高】CI 门禁覆盖面与本地验证链不一致，且存在整文件豁免

- `ci.yml` 第 37 行（ruff）与第 49 行（compileall）都只覆盖
  `core/ engine/ ai/ web/ scripts/ backtest/ strategies/ indicators/ config/ drl/`，
  **缺少 `exchange/`、`factors/`、`tests/`**；而 `docs/REDEV_GUIDE.md` §4 本地验证链明确包含 `exchange factors`。
- `.coveragerc` 第 3 行 `source` 同样**没有 `exchange`、`factors`** → 这两个核心模块完全不在覆盖率门禁视野内。
- `ruff.toml` 第 14-25 行对 6 个文件整文件豁免 E9+F：
  `config/settings.py`、`drl/evolve_engine.py`、`drl/model_zoo.py`、`drl/walkforward.py`、`strategies/meta.py`、`drl/factor_miner.py` —— 其中持续进化引擎（evolve_engine/model_zoo/factor_miner）恰是 AI 自动部署的高风险区。
- 影响：静态检查与覆盖率都有系统性盲区；"门禁全绿"不等于核心模块被检查过。

### 2.3 【高】无 Windows 平台 CI

- 项目主平台是 Windows（`start.bat` 纯 ASCII 约束、GBK 编码陷阱、`winloop`），但 CI 只在 `ubuntu-latest` 跑。
- Windows 专项问题（bat 解析、第三方库默认编码、路径/端口行为）**完全不会被 CI 捕获**，只能靠人肉双击验证。
- 影响：REDEV_GUIDE §F1/F2 的红线没有自动化保障。

### 2.4 【中】CI 无手动触发、无计划任务、无产物归档

- `ci.yml` `on:` 只有 `push`/`pull_request`，**无 `workflow_dispatch`**（手动触发）、无定时 cron。
- 无覆盖率 HTML / JUnit XML / 日志产物上传；失败排查要靠重跑日志。
- 本地已有 `scripts/daily_health_report.py`、`service_supervisor.py` 等运维能力，但未接入 CI/计划任务。

### 2.5 【中】无本地 pre-commit，验证链靠人肉

- 仓库无 `.pre-commit-config.yaml`、无 git hooks（已用 glob 确认），`scripts/` 下也没有 hooks 目录。
- `docs/REDEV_GUIDE.md` §4 的验证链（compileall→pytest→check_js→双引擎基线）全靠提交者自觉执行。
- `package.json` 与 `scripts/*.py` 并存两套命令入口，但没有一个 `verify_all` 把整条链串起来。

### 2.6 【中】依赖策略：运行/开发依赖混在一个 lock，无哈希、平台未拆分

- `requirements-lock.txt` 由 `pip freeze` 生成（文件头自述），不是 `pip-tools`/`uv` 的可哈希 lock；传递依赖范围无法完全锁定。
- 运行依赖与开发/测试依赖混在一起（`pytest`、`coverage`、`pytest-cov` 也在 lock），`pytest-asyncio` 这种关键 dev 依赖却漏了（REDEV_GUIDE §F8 已把它列为"重新装环境易漏"项）。
- 平台相关包（`winloop`、`cupy-cuda12x`、`nvidia-*`）未拆分到 `requirements-windows.txt` / `requirements-linux.txt` 之类。

### 2.7 【中】代码质量门禁深度不足

- ruff 只开 E9+F，无风格/复杂度/可维护性规则；`target-version = "py310"` 而项目运行在 Python 3.13（`ruff.toml` 第 8 行）。
- 本机 `.venv` 里已装 `mypy`（`Scripts/mypy.exe` 存在），但**仓库无 `mypy.ini`/`pyproject.toml` 类型检查配置，CI 未跑**。
- 覆盖率只有全量 65% 单一门槛，无模块级最低线；慢测试（DRL 训练类）与快测试未分层，CI 每次全量跑。

### 2.8 【低】仓库治理细节

- `docs/REDEV_GUIDE.md` §1 记录 2026-09-01 时工作区约 145 个文件未提交，git 历史最新提交滞后——基线快照纪律仍缺工具化保障。
- `.github/` 只有 CI workflow，无 issue/PR 模板、无 dependabot。
- 文档与实际配置存在漂移：如 `docs/LIVE_READINESS.md` 描述 CI 含"17 训练测试排除段"，但当前 `ci.yml` 已无该段。
